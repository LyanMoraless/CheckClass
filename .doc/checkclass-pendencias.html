Gap Política de leitura do documento de fechamentoBackend + Security

"Open Question 4" do Solution Architect ("quem pode baixar/ler o documento de fechamento") nunca foi respondida. Consequência concreta, já observada pelo Project Guardian: attendance_closure_document não tem política RLS interativa de leitura — só o GUC do job não-assistido enxerga a linha — então o indicador archived: true em /v1/me/attendance nunca dispara na prática hoje.

Por quê isso importa: não é um bug — degrada com segurança (o endpoint cai no formato silencioso pré-existente) — mas o recurso "ver que meu período está arquivado" simplesmente não aparece para ninguém até essa política existir.

Frente 12 — Vínculo de Dispositivo Institucional

Revisão Coordenação não vê o inventário de máquinas institucionaisDecisão de negócio

InstitutionalMachineController (list/get) está restrito a Direção/Reitoria — conservadorismo do Backend Agent, não uma regra confirmada. VIEW_DEVICE_BINDINGS (RULE-DEV-16) é mais amplo e já inclui coordenação. Candidato a revisão do usuário, não um erro já confirmado.

Gap RULE-DEV-18 sem UI — revogação administrativa de BYODBackend + Frontend, pequeno

Falta endpoint de busca de dispositivo pessoal por personId — a listagem de vínculos só expõe deviceIdentityId cru, sem tela de revogação administrativa. Autosserviço (o próprio dono revogando o próprio BYOD) já funciona integralmente hoje; só a revogação feita por um administrador em nome de outra pessoa está sem caminho de UI.

Nota "Titular padrão" de VIEW_DEVICE_BINDINGS não é grant automáticoConfig, não é bug

RULE-DEV-16 (coordenação + diretoria) é diretriz de configuração, não um grant automático do sistema — o admin do tenant precisa criar o permission_group correspondente. Mesmo padrão de todo o enum Permission na plataforma. Registrado aqui só para não ser lido como pendência técnica quando não é.

UX Duas convenções assumidas sem confirmação explícitaRevisão de UX

O Frontend Agent tomou duas decisões de UX sem pedir confirmação: a posição de "Meu dispositivo" na navegação, e a distinção entre InfoBanner/ErrorBanner para diferenciar oferta ambiente de cerimônia deliberada de vínculo. Nenhuma reclamação registrada até agora — item de revisão, não de correção.
